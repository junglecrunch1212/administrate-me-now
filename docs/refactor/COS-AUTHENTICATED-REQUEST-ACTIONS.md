# Authenticated conversation actions

MODERNIZE: a clear current private member instruction can supply action intent
without a redundant manual allow-once. OpenClaw independently verifies a signed
source/action ticket in its supported hook; AdministrateMe rechecks the retained
human instruction, grounded exact action, current member/provider authority and
expiry. This is a machine policy decision, never a fabricated human approval.
Other native host policies can still block the tool. Retrieved/quoted text and
model output cannot grant themselves authority.

This slice connects private iMessage, signed member dashboard chat and receiver-
authenticated direct Gmail input to the existing Apple Reminder confirmation,
execution, bridge ledger and terminal status. The pinned `llm-task` supplies only
semantic evidence. Current grant/list checks, observation mode, final bridge
admission and audited terminals remain independent. Exact due instants are
preserved; only `succeeded` proves the reminder was created. Legacy pending
confirmations retain their original identifier, due time and approval semantics;
policy changes do not release them. Gmail final replies reuse the existing
allowlist, governance, rate limit, privacy guard and durable send ledger, with
exact original account, recipient and RFC thread binding. An unknown send never
automatically retries.

Recovery after new history is feature revocation on this schema-aware runtime:

```bash
python -m bootstrap.request_actions --instance-dir "$ADMINME_INSTANCE_DIR" disable
python -m bootstrap.request_actions --instance-dir "$ADMINME_INSTANCE_DIR" status
```

Run these using the deployed release interpreter and actual instance directory.
The control is atomically written, private and read at new dispatch, action/reply
authorization and final Apple bridge admission. It changes no provider grant,
source configuration or event history. Existing acquisition, private context,
manual actions and self-replies continue under their existing authority. After
recovery, check normal readiness and existing source status; a pending new policy
action must be denied before provider contact. Enable preserves a revocation
cutoff, so pre-recovery pending requests do not resume:

```bash
python -m bootstrap.request_actions --instance-dir "$ADMINME_INSTANCE_DIR" enable
```

Before any new event is written, an updater failure can restore the known-working
predecessor normally. After new conversation/grounding/approval history, do not
claim predecessor replay compatibility or roll back to an older schema registry.
Keep the schema-aware runtime, revoke this route, then repair the scoped failure.

Focused proof uses real application intake, event/approval stores, native hooks,
bridge dispatcher and Gmail send adapter with isolated model/provider boundaries.
It does not prove arbitrary model reasoning, live provider success, automatic
completion of broader CoS work, or modify/cancel workflows for every provider.
Other provider actions, recent-work discovery and durable multi-step execution
remain subsequent usable slices.
